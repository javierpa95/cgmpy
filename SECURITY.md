## ⚠️ Medical Data & Privacy — Read Before Contributing

CGMPy processes **Continuous Glucose Monitoring (CGM)** data, which is classified
as **Protected Health Information (PHI)** under HIPAA (US) and personal health
data under GDPR (EU) and similar regulations.

### Strict prohibitions

- ❌ **Never commit** real patient data, real CGM exports, or any data that
  contains personal identifiers (name, email, device serial numbers,
  timestamps combined with identifiers, etc.).
- ❌ **Never log** patient identifiers, even in `print()` or `logger.info()`
  statements. Sanitize logs.
- ❌ **Never hardcode** credentials, API keys, or database URLs.
- ❌ **Never share** bug reports with attached real CSVs. Always anonymize
  before sharing.

### Examples and test fixtures

All CSVs, Parquet files, and DataFrames used in:

- `tests/fixtures/`
- `tests/clinical/`
- `examples/**/data/`

**must be either:**

1. **Fully synthetic** (generated by `scripts/generate_fixtures.py` or similar), or
2. **Fully anonymized**: timestamps shifted by a random offset, patient IDs
   replaced with `PATIENT_001`, `PATIENT_002`, ..., ages binned, etc.

A simple anonymization script is provided at `scripts/anonymize_cgm.py`. Run
it on any real dataset **before** adding it to the repo.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a security vulnerability in CGMPy, please email:

📧 **javierpenatearrieta@gmail.com**

Include the following:

- A clear description of the vulnerability.
- Steps to reproduce.
- The affected version(s).
- Any potential impact.

You should expect an initial response within **72 hours**. We will work with
you to understand the issue, coordinate disclosure, and (if applicable) ship a
patch before a public advisory.

## Security Best Practices for Contributors

When contributing code that handles data:

1. **Validate all input** — assume CGM CSVs may have malformed rows, wrong
   delimiters, missing columns, or non-numeric glucose values.
2. **Use the logging module, not print** — and make sure PHI is not logged.
3. **Avoid `eval`, `exec`, `pickle` on user-provided data** — these can lead
   to arbitrary code execution.
4. **Pin dependencies in CI** — but allow flexibility for end users.
5. **Run `bandit`** locally before opening a PR: `bandit -r cgmpy/`.
