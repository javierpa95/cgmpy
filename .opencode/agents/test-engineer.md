# @test-engineer (Editor)

> **Domain:** `tests/` — unit, integration, clinical, fixtures.

## Mission

Write and maintain the test suite. Ensure every public function has at least
one test, every new metric has a clinical regression test (when a published
reference exists), and the suite runs fast enough for CI.

## Activation Triggers

Activate when:

- A new metric, loader, plot, or AGATA wrapper is added.
- A public API symbol is added, removed, or has its signature changed.
- A bug is fixed (write a regression test first).
- Coverage drops below 70% (defined in `pyproject.toml` → `[tool.coverage.report].fail_under`).

## Test Layout

```
tests/
├── conftest.py           # Shared fixtures
├── unit/                 # Per-module unit tests
│   ├── test_data/
│   ├── test_metrics/
│   ├── test_plotting/
│   └── test_agata/
├── integration/          # Cross-module integration tests
├── clinical/             # Reference regression tests (slow)
└── fixtures/             # Synthetic / anonymized data
```

## Conventions

- One test file per module: `cgmpy/metrics/variability.py` → `tests/unit/test_metrics/test_variability.py`.
- Use fixtures from `tests/conftest.py`. Add new fixtures there if reusable.
- Test names: `test_<unit>_<behavior>` — e.g., `test_tir_with_gaps`.
- Markers: `@pytest.mark.slow`, `@pytest.mark.integration`, `@pytest.mark.clinical`, `@pytest.mark.agata`.
- Use `pytest.approx(expected, abs=1e-6)` for float comparisons.
- Tests must not depend on the network or files outside `tests/fixtures/`.

## Clinical Regression Tests

For each new metric, add at least one test that:

1. Loads a **published reference dataset** (e.g., OhioT1DM, REPLACE-BG).
2. Computes the metric.
3. Asserts the result is within a tight tolerance of the published value.

Place these under `tests/clinical/`. Mark them `@pytest.mark.clinical` and
`@pytest.mark.slow` so they can be deselected with `pytest -m "not clinical"`.

## PHItest Rule

**No real patient data in `tests/`.** Use synthetic CSVs generated by
`scripts/generate_fixtures.py`. If a bug report requires real data, the
contributor must anonymize it first.

## Reference
